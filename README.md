# 运行状态（astrbot_plugin_status）

**当前版本：0.1.0。** 元数据声明需要 AstrBot 4.28.2 或更高版本。

`/status` 手动查询 bot 运行状态。只读、不轮询、不推送、不改任何策略。

## 安装与维护

本插件由 [leekooyo](https://github.com/leekooyo) 维护。在 AstrBot 中选择「通过仓库地址安装」，填写 `https://github.com/leekooyo/astrbot_plugin_status`。升级前请备份 AstrBot 的插件配置；需要排查或改进时，可在本仓库提交 Issue。

## 命令

| 命令 | 可使用者 | 内容 |
| --- | --- | --- |
| `/status` | 所有人 | 概览；群内追加当前群状态 |
| `/status help` | 所有人 | 当前身份可用的命令 |
| `/status groups [页码]` | 管理员私聊 | 群列表：群名、群 ID、生效模式、限制阶段 |
| `/status group <群ID>` | 管理员私聊 | 单群详情与策略解释 |
| `/status bans [页码]` | 管理员私聊 | 已知禁言与恢复等待 |
| `/status plugins [页码]` | 管理员私聊 | 插件标识、显示名、版本、加载/启用状态 |
| `/status runtime` | 管理员私聊 | 运行详情与各数据来源的更新时间 |
| `/status refresh` | 管理员私聊 | 刷新群列表缓存（不扫描禁言） |

* 机器人管理员以 AstrBot 的 `admins_id` 为准；QQ 群管理员没有跨群查询权限。
* 管理员在**群内**使用管理子指令只会收到「请私聊使用该查询」，不在群内输出，也不主动私信。
* 普通用户调用管理参数直接返回权限提示，不加载任何跨群数据、不触发刷新。
* 页码必须是正整数；群 ID 使用纯数字群号；未知参数返回用法，不默认执行其他查询。

## 权限与信息边界

公开概览只包含：bot 显示名、连接状态、运行时长、已加入群数、已知禁言记录数、恢复等待数；
群内再加当前群的模式、插件/默认聊天放行结论与 QQ 限制情况。**不**展示其他群名称与 ID、
不展示 CPU、内存与插件总数。

## 数据来源

| 数据 | 来源 |
| --- | --- |
| 群模式、禁言阶段、禁用插件 | gatekeeper 的只读快照 `get_status_snapshot()`（需 gatekeeper 0.4.0+） |
| 群列表 | 本地缓存 → gatekeeper 最近一次完整结果 → QQ 适配器（至多 1 次） |
| 连接状态、启动时间 | 框架平台状态 / 后端进程 |
| CPU、内存 | 本进程指标（psutil） |
| 插件清单 | 框架本地插件管理状态，含框架记录的加载失败项 |
| 框架会话开关 | `SessionServiceManager`（`/status group` 详情） |

gatekeeper 不可用（未安装、已停用、版本过低、快照异常）时，群数、连接、运行、插件信息仍可用，
限制数字显示「—」，`/status bans` 明确提示「记录未知（不是 0 条）」而不渲染成空表。
gatekeeper 总控关闭时，历史禁言记录不再作为当前生效限制展示。

## 缓存与请求预算

* 群列表 TTL 900 秒，用单调时钟计时；gatekeeper 已有新鲜完整列表时直接导入，**不重新计时**。
* 群列表以**成员列表**为主表（群名取最新），快照只补策略；快照还没收录的新群按 gatekeeper
  默认模式解释，限制状态显示「无记录」并单独说明，不推断为已检查正常。
* 收到 bot 自身加退群事件后记录失效标记与时间；只有**晚于该时间**采集到的快照才能消除标记，
  更早的快照不会被采纳，也不会给旧列表续期。
* 同时到达的冷查询共享同一个请求任务；手动刷新也复用正在进行中的任务，同样消耗 60 秒冷却。
* 单次请求超时 5 秒，不自动重试；失败后保留旧列表并标注「缓存」，60 秒内不重复补拉。
  此时 `/status refresh` 明确回复「刷新失败，保留上次缓存」并给出原采集时间。
* 手动刷新受 60 秒冷却约束，失败同样消耗冷却。
* 状态卡片按「账号 + 公开/管理 + 会话位置 + 子命令 + 参数」复用 30 秒，上限 64 张。

典型请求量：缓存有效时 0 次 QQ 查询；冷缓存 1 次群列表查询。`/status plugins` 与
`/status runtime` **只读本地**，冷缓存也不发群列表请求（`runtime` 对未取过的群列表显示
「尚未获取」）；`groups` / `bans` / `plugins` / `runtime` 均不逐群请求禁言状态。

## 输出

状态结果渲染为浅色仪表盘图片（逻辑宽 900 px，2 倍输出）。渲染失败时用**同一视图**输出
等权限文字，不额外刷新数据。帮助、权限与语法提示直接使用文字。

图片写入 AstrBot 的 `data/temp/`。30 秒复用只是不再新生成同一张卡片，**不等于文件到期删除**；
实际回收由框架既有的 `TempDirCleaner` 按目录容量策略执行，不额外建清理器。

`/status plugins` 的「加载失败」来自框架的 `failed_plugin_dict`。框架在加载失败后会把该插件
从注册表移除，因此这些行是单独并入的，既不计入「已加载」也不计入「已启用」。

## 配置

| 配置项 | 说明 |
| --- | --- |
| `target_platform_id` | 仅在同一 AstrBot 里连接了多个 aiocqhttp 账号时需要填写。留空且只有一个账号时自动使用；无法确定目标账号时明确提示需要配置，不合并不同账号的数据。 |

## 依赖

只用框架自带依赖：`psutil`、`Pillow`（字体与换行复用 `astrbot.core.utils.t2i` 的
`FontManager` / `TextMeasurer`）。不访问插件市场、不联网检查版本、不调用模型。

## 与 gatekeeper 的关系

单向依赖：status 读取 gatekeeper 的公开快照，gatekeeper 不感知 status，两者可独立启停。
status 不穿透 gatekeeper 的静默：群被设为 `mute`、或 `llm` 模式下 handler 被剔除时，
`/status` 同样不会响应；被单群禁用的插件列表也不会被 status 绕过。
